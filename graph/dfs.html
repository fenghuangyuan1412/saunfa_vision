深度优先搜索

深度优先搜索（Depth-First Search，DFS）沿着一条路径「一往直前」：进入一个新格子就立刻标记并继续深入，走投无路时回溯换方向。它用递归栈（或显式栈）实现，与 BFS 的队列恰好相反，因此先找到的路径未必最短，但空间更省、写法更简洁。

算法原理

维护访问标记 vis[]：约定进入即标记（压栈时就置 vis=1），这样每个格子最多被尝试一次。递归框架：进入当前格、压栈；按固定邻居顺序（本页为 下→右→上→左）找到第一个未访问的可走邻居就深入；四个方向都走不动时弹栈回溯。用显式栈模拟时行为完全一致，还能避免递归过深的问题。

procedure DFS(u):
    vis[u] = 1            // 进入即标记，避免重复进入
    stack.push(u)         // 当前递归路径 = 栈内序列
    if u = target: 找到一条路径，返回成功
    for v in neighbors(u) in order 下,右,上,左:
        if v 合法 且 not vis[v]:
            if DFS(v): return true   // 通向终点的路径保留在栈中
    stack.pop()           // 回溯：此路不通，退出当前格
    return false

DFS 找一条路径 vs BFS 找最短路：DFS 依赖栈的「后进先出」，钻到第一条触达终点的路径就停，长度可能远超最短；BFS 用队列逐层扩展，第一条触达终点时距离必最短。反过来，DFS 只保存当前路径与递归现场，内存占用通常小于 BFS 的整层队列，且天然适合枚举全部路径、连通分量等需要「深入到底」的任务。

警告：爆栈风险 与 vis 时机

① 递归实现 DFS 时栈深等于路径长度，大图 / 长迷宫（如 10^5 级别的深图）可能爆栈（Stack Overflow），竞赛中应改用显式栈迭代，或在评测环境允许时提升栈大小。② vis 必须在进入（压栈）时标记而不是弹出时标记：压栈即标记保证每个结点至多入栈一次，复杂度为 O(n+m)；若出栈才标记，同一结点会被反复压入，复杂度与内存都可能爆炸。

复杂度分析

指标量级说明
时间复杂度（一般图）O(n + m)进入即标记：每个点压栈一次，每条边检查一次
时间复杂度（网格）O(RC)R×C 格，每格至多 4 个邻居
空间复杂度O(n) / 路径长栈内只保存当前路径：迷宫上最坏 O(RC)（即递归深度），通常远小于 BFS 整层队列；另需 O(RC) 的 vis 数组
路径质量找到的是第一条 DFS 路径，无权图最短路须用 BFS

应用与局限

DFS 是众多图论算法的骨架：求连通分量、拓扑排序（DFS 逆后序或结合入度）、判环（白灰蓝三色标记）、强连通分量（Tarjan / Kosaraju）、割点割边，以及迷宫全部路径枚举与组合搜索（剪枝优化的舞台）。本页演示的「进入即标记 + 回溯弹栈」适合求一条可行路径。局限：无条件深入使它在无权最短路问题上给不出最优解；深图递归有爆栈风险；枚举全部路径时规模可能指数级，需要剪枝。
