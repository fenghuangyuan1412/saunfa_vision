Bellman-Ford 与 SPFA

Bellman-Ford 与它的队列优化版 SPFA（Shortest Path Faster Algorithm）都能处理带负权边的单源最短路，并且能检测负环。它们不像 Dijkstra 那样「取最小即定稿」，而是允许一个结点的距离被反复改进，因而可以安全地使用负权边。

算法原理

Bellman-Ford：松弛 V−1 轮

把每条边按任意顺序扫一遍称为一轮松弛。一轮结束后，「最短路径只含 1 条边」的结点距离已正确；两轮后 2 条边的也正确……于是第 k 轮结束后，所有边数 ≤ k 的最短路都已就位。而无负环时结点 v 的最短路径可以取成简单路径（若路径重复经过某结点，去掉中间那个环不会让路更长），至多 V−1 条边——这就是 V−1 轮足够的原因，也是它能处理负权的原因。

procedure BellmanFord(s):
    for v in V: d[v] = +∞; prev[v] = NIL
    d[s] = 0
    repeat V - 1 times:
        anyUpdate = false
        for (u, v, w) in E:                   // 全体边扫一轮
            if d[u] ≠ +∞ 且 d[u] + w < d[v]:
                d[v] = d[u] + w; prev[v] = u
                anyUpdate = true
        if not anyUpdate: break               // 提前收敛
    // 负环检测：第 V 轮仍能松弛则存在负环
    for (u, v, w) in E:
        if d[u] ≠ +∞ 且 d[u] + w < d[v]: report "存在负环"

SPFA：只把「刚被更新的点」再排队

Bellman-Ford 的浪费在于：一轮里绝大多数边根本不可能更新任何东西。注意到「只有 u 的 d 变小了，从 u 出发的边才可能再次生效」，于是用队列做优化：只把刚被更新的点放进队列等待处理，取出队头 u 松弛它的出边，谁被改进了谁入队。inq[v] 标记 v 是否已在队中，保证一个结点在队中只占一份，避免同一结点被重复堆进队列造成规模爆炸；因此「出队后必须先把 inq 置回 false」，它才允许因再次被改进而入队。

procedure SPFA(s):
    for v in V: d[v] = +∞; prev[v] = NIL; inq[v] = false; cnt[v] = 0
    d[s] = 0
    queue.push(s); inq[s] = true; cnt[s] = 1      // cnt[v]：当前最短路上的边数
    while queue not empty:
        u = queue.pop(); inq[u] = false           // 出队后才允许再次入队
        for (u, v, w) in E:
            if d[u] + w < d[v]:
                d[v] = d[u] + w; prev[v] = u
                cnt[v] = cnt[u] + 1                // 到 v 的路径多了一条边
                if cnt[v] ≥ V: report "存在负环"
                if not inq[v]:
                    queue.push(v); inq[v] = true

负环的两种判据：① 统计每个点的入队次数，某点入队 ≥ V 次即判定负环；② 维护 cnt[v]（= cnt[u]+1，即当前最短路包含的边数），一旦 cnt[v] ≥ V 判定负环。两者都源于「无负环时最短路径至多 V−1 条边」；判据 ② 触发更早，只需多开一个数组。

危险：负环上「最短路」无定义

只要源点能够到达某个负环，源点到该环以及环可达的一切结点的最短距离就是 −∞：每绕环一次总权再降一点，有限的最短路径并不存在，prev[] 也会绕成环而无法回溯出「路径」。因此负环存在时算法的正确输出是「图中存在负环」这一判定，而不是一组 d[] 数值。常见处理：把负环上的点标记为特殊值后再回答查询；差分约束系统里「无解」正是由负环给出的。若只想判断「从源出发是否存在负环」，Bellman-Ford 跑满 V 轮、看第 V 轮是否仍能松弛即可。

警告：SPFA 会被构造数据卡

SPFA 平均很快（经验上约 O(kE)，k 为结点平均入队次数，随机图上接近 2），但最坏仍是 O(VE)，而且这个最坏可以被出题人定向构造：网格图、随机稀疏图补若干边、「链式菊花图」等经典反图都能把它逼到与 Bellman-Ford 同级甚至更慢，竞赛中据此卡 SPFA 的题十分常见。启发式改进 SLF（d[v] 小于队头就插到队头）与 LLL（平均标号算法）在随机数据上有效，但不改变最坏界。结论：边权非负时优先用堆优化 Dijkstra（O((V+E)\log V)，稳定）；确有负权（或需要负环判定）时才用 SPFA / Bellman-Ford。Bellman-Ford 的边表三重循环常数极小、最好写，也最适合与「限步数 / 分层图」一类的扩展搭配。

复杂度分析

算法 / 指标量级说明
Bellman-Ford 时间O(V·E)V−1 轮 × 每轮扫全部边；实际常在远少于 V−1 轮后收敛（加 anyUpdate 提前退出）
SPFA 时间（最坏）O(V·E)可被构造数据（网格图、链式菊花图等）逼到此界
SPFA 时间（平均 / 随机图）约 O(k·E)，k ≈ 2k 为结点平均入队次数，随机数据上通常快于 Bellman-Ford 与堆优化 Dijkstra
空间（两者）O(V + E)边表 / 邻接表 + d[] + prev[] + inq[] + cnt[] + 队列（≤ V 项）
边权要求可含负权边；但源点可达范围内不得有负环（否则最短路无定义，算法只报告负环）
负环检测入队次数 ≥ V；或 cnt[v]=cnt[u]+1 ≥ V；或 Bellman-Ford 第 V 轮仍能松弛

应用与局限

应用：① 含负权边的最短路——把「收益」取负即为求最大收益路（赚最多钱的航线）、任务网络中的时间盈余；② 差分约束系统：把约束 x_i − x_j ≤ c 写成边 j→i 权 c，一组最短路解即满足全部约束，负环即无解；③ 限步数最短路：Bellman-Ford 的第 k 轮天然给出「至多 k 条边」的答案，打折机票（最多 K 次中转）这类题就是它加上分层图；④ 判负环（汇率套利检测）；⑤ 图不大而代码求简时，三重循环的 Bellman-Ford 最不容易写错。

局限：① 最坏 O(VE)，大图稠密图吃不消，SPFA 的最坏界还可被人为构造；② 存在负环时给不出距离；③ 与 Dijkstra 一样是单源算法，多源请用 Floyd；④ 不具贪心定稿性质，无法与 A* 之类的启发式结合。
