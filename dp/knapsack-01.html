0/1 背包

0/1 背包（Knapsack）：给定容量 W 和 n 件物品，第 i 件重量 w[i]、价值 v[i]，每件最多选一次（选 0 件或 1 件，故称 0/1），求总重量不超过 W 的前提下能获得的最大总价值。它是 DP 的里程碑问题：一维转移数组的枚举方向直接决定答案对错。

算法原理

六要素速览
  • 状态定义：dp[i][j] = 只考虑前 i 件物品、背包容量为 j 时的最大总价值。
  • 转移方程：dp[i][j] = max(dp[i-1][j], dp[i-1][j - w[i]] + v[i])，第二项仅在 j ≥ w[i] 时存在。
  • 边界条件：dp[0][j] = 0（一件物品都没有，价值恒为 0）。
  • 填表顺序：i 从 1 到 n，每行内 j 从 0 到 W（第 i 行只依赖第 i-1 行）。
  • 答案位置：右下角 dp[n][W]。
  • 方案回溯：从 (n, W) 反向走，dp[i][rem] > dp[i-1][rem] 说明第 i 件被选中，剩余容量减去 w[i]。

转移的两支对应两种互斥决策：不选第 i 件，最优值与「前 i-1 件、容量 j」相同（正上方格子）；选第 i 件，则要先腾出 w[i] 的容量，最优值是「前 i-1 件、容量 j - w[i]」加上 v[i]（左上方格子）。两个来源都来自第 i-1 行，这正是「每件只能选一次」的体现。

procedure Knapsack01(w[1..n], v[1..n], W):
    for j = 0 to W: dp[0][j] = 0            // 边界：没有物品
    for i = 1 to n:                         // 逐行填表
        for j = 0 to W:
            dp[i][j] = dp[i-1][j]           // 决策一：不选第 i 件
            if j >= w[i]:                   // 装不下就没有「选」这一支
                dp[i][j] = max(dp[i][j], dp[i-1][j - w[i]] + v[i])
    return dp[n][W]

procedure Recover(dp, w, n, W):             // 方案回溯
    rem = W; items = []
    for i = n downTo 1:
        if dp[i][rem] > dp[i-1][rem]:       // 变大 => 第 i 件一定被选中
            items.append(i); rem = rem - w[i]
    return items

空间压缩：为什么必须逆序枚举 j

第 i 行只依赖第 i-1 行，因此可以把二维表压成一维数组 f[0..W]，原地滚动：

for j = 0 to W: f[j] = 0
for i = 1 to n:
    for j = W downTo w[i]:        // 关键：逆序！
        f[j] = max(f[j], f[j - w[i]] + v[i])
answer = f[W]
逆序的因果

写成 max(f[j], f[j - w[i]] + v[i]) 后，f[j - w[i]] 必须是「还没考虑第 i 件物品」时的值（等价于二维的 dp[i-1][j - w[i]]）。

  • 逆序（j 从 W 递减到 w[i]）：更新 f[j] 时，比它小的下标 j - w[i] 这一轮还没被访问，仍是上一轮（前 i-1 件）的旧值 —— 语义正确。
  • 正序（j 从 w[i] 递增到 W）：f[j - w[i]] 本轮已经更新过，里面可能已经含第 i 件，再加一次 v[i] 就等于把同一件物品选了两遍 —— 这恰好是完全背包（每件可选无限次）的正确写法。

一句话记忆：0/1 背包逆序，完全背包正序。本页演示的下方小面板会把两种顺序的差异都跑一遍。

复杂度分析

指标量级说明
最优时间复杂度O(nW)状态数 n × (W+1)，每个状态转移 O(1)
平均时间复杂度O(nW)与物品重量、价值分布无关（只与 W 有关）
最坏时间复杂度O(nW)同上；伪多项式——W 以二进制给出时是指数级
空间复杂度O(W)一维滚动数组；保留二维表 O(nW) 才能直接回溯方案
方案回溯O(n)需完整 dp 表；一维版本要另存每轮选择

应用与局限

  • 伪多项式时间：O(nW) 里的 W 是数值而非输入长度。若 W = 10⁹，DP 直接不可行，只能转向搜索、 meet-in-the-middle（折半枚举 O(2^(n/2))，适合 n ≤ 40）或贪心近似（分数背包按性价比排序即最优）。判断该用哪种做法，第一件事就是看 n 与 W 谁小。
  • 恰好装满：把「容量不超过」改成「恰好装满」，只需改初始化：一维版本 f[0] = 0、其余 f[j] = -∞（二维版本 dp[0][0] = 0、dp[0][j] = -∞）。这样不可达状态不会被当成价值 0 参与 max，最后 f[W] 仍为 -∞ 就表示无解。求最小价值的「恰好装满」则把 -∞ 换成 +∞ 并把 max 换成 min。
  • 方案计数：dp[i][j] += dp[i-1][j] + dp[i-1][j-w[i]]（不选与选的数目相加），同样逆序；完全背包计数则正序。注意取模。
  • 最少物品数：把 max 换成 min、权值换成 1，即「凑出金额所需的最少硬币数」的 0/1 版本（无限个则是完全背包）。
  • 二维费用背包 / 分组背包：状态再加一维容量，或在「组」外面再套一层枚举，转移结构不变。

局限：DP 只能给出「最大值」，若问题还要求「方案数最多中的字典序最小」之类附加目标，就需要在状态里多带信息或二次 DP；同时 O(nW) 的常数虽然小，仍受 W 数值上界的硬约束。
