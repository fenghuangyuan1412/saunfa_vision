最长公共子序列

最长公共子序列（Longest Common Subsequence，LCS）求的是两个序列共有的子序列中最长者的长度。它是二维 DP 的教科书写法，也是 diff、版本比对、DNA 序列分析等工具的算法内核。本页用经典例子 A = ABCBDAB、B = BDCABA 逐格填表，并从表尾回溯出一条实际方案。

算法原理

子序列（subsequence）允许跳过字符但不改变相对顺序；子串（substring）必须连续。因此「公共子串最长长度」是另一个更简单的问题（可以用 DP dp[i][j] = dp[i-1][j-1]+1 且不等时归零，或后缀数组 / SAM），而 LCS 的不等分支要在「上」与「左」之间取最大值。本页下标从 1 开始：A[i] 表示 A 的第 i 个字符。

状态定义：dp[i][j] = A 的前 i 个字符与 B 的前 j 个字符的 LCS 长度。转移：

  • A[i] == B[j]：dp[i][j] = dp[i-1][j-1] + 1。这个公共字符必然可以作为某个最优 LCS 的末位（否则把它接上去只会更长，矛盾）。
  • A[i] != B[j]：dp[i][j] = max(dp[i-1][j], dp[i][j-1])。两个字符不可能同时出现在公共子序列的末尾，丢弃 A[i] 或丢弃 B[j] 至少有一个是安全的，两种都试。

边界：dp[0][j] = dp[i][0] = 0——空串与任何串的最长公共子序列长度为 0。填表顺序按行（或按列）从左到右、从上到下，保证 dp[i-1][j-1]、dp[i-1][j]、dp[i][j-1] 都已算好。答案在 dp[m][n]。

procedure LCS(A[1..m], B[1..n]):
    for i = 0 to m: dp[i][0] = 0            // 边界：B 取空串
    for j = 0 to n: dp[0][j] = 0            // 边界：A 取空串
    for i = 1 to m:
        for j = 1 to n:
            if A[i] == B[j]:
                dp[i][j] = dp[i-1][j-1] + 1     // 来源：左上角
            else:
                dp[i][j] = max(dp[i-1][j], dp[i][j-1])   // 来源：上方 / 左方

procedure backtrack(i, j):                  // 从右下角还原一条方案
    if i == 0 or j == 0: return ""
    if A[i] == B[j]: return backtrack(i-1, j-1) + A[i]
    if dp[i-1][j] >= dp[i][j-1]: return backtrack(i-1, j)
    else:                          return backtrack(i, j-1)

// 求长度时可滚动到 O(min(m,n)) 空间；要回溯方案必须保留整张表
提示：只要长度还是要方案

只求长度时，dp 的两行（或一行 + 左上角临时变量）足够，空间降到 O(min(m, n))。一旦需要输出方案或统计方案数，就得保留整张 O(mn) 的表；也可以用「Hirschberg 分治」在 O(n) 空间内输出方案，代价是把时间常数翻倍。

复杂度分析

指标量级说明
最优时间复杂度O(mn)自底向上必须填满整张表，与字符串内容无关
平均时间复杂度O(mn)每格常数次比较与取最值；字符表越大，匹配概率越低但格数不变
最坏时间复杂度O(mn)不存在退化，上界即下界（DP 版本）
空间复杂度O(mn)保留全表用于回溯；只求长度可滚动到 O(min(m,n))；Hirschberg 分治可 O(n) 空间 + 方案
位并行加速O(mn / word)Bit-parallel LCS（Allison–Dix）用一个机器字表示一行，实际快 30~60 倍

应用与局限

LCS 是文本差异比较的基础：diff、Git 的版本对比、IDE 的合并冲突提示，本质都是把「最长公共子序列」当作未改动部分，剩余部分即增删。它与编辑距离互为镜像——只允许插入与删除的编辑距离 = m + n − 2·LCS；反过来 LCS 也能由编辑距离推出。它还等价于最短公共超序列（SCS）：SCS 长度 = m + n − LCS。在生物信息里，两条 DNA / 蛋白序列的比对打分模型是 LCS 的加权推广（Needleman–Wunsch）。

局限有三点：其一，O(mn) 对超长序列（全基因组级别）不可接受，工程上改用启发式比对（BLAST 先用 k-mer 种子定位）。其二，LCS 只反映「顺序一致的公共部分」，对局部相似性要靠 Smith–Waterman（局部比对）等变形。其三，多于两条序列时，把 dp 推广到 k 维需要 O(n^k)；当 k 作为输入的一部分时，多序列 LCS 是 NP-hard 的，只能近似或改用 SP（sum-of-pairs）打分启发式。
