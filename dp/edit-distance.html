编辑距离

编辑距离（Levenshtein Distance）衡量把字符串 A 变成字符串 B 最少需要多少次单字符操作（插入、删除、替换）。它是二维 DP 的另一张经典表格，也是拼写纠错、模糊匹配、序列比对这些真实功能的核心度量。本页用 A = book、B = back 演示逐格填表与操作回溯。

算法原理

状态定义：dp[i][j] = 把 A 的前 i 个字符变成 B 的前 j 个字符所需的最少操作数（本页下标从 1 开始，A[i] 是第 i 个字符）。最后一次操作只可能落在三个位置之一，对应表格里的三个来源方向：

  • 删除 A[i]：先花 dp[i-1][j] 把前 i-1 个变成 B 的前 j 个，再删掉 A[i]。→ 来源上方，代价 +1。
  • 插入 B[j]：先花 dp[i][j-1] 把 A 的前 i 个变成 B 的前 j-1 个，再在末尾补一个 B[j]。→ 来源左方，代价 +1。
  • 替换 / 匹配：把 A[i] 改成 B[j]（相同则不改，代价 0），前 i-1 与前 j-1 已经对齐。→ 来源左上角，代价 + (A[i] != B[j] ? 1 : 0)。

边界很直白：dp[i][0] = i（把长度为 i 的串变成空串，只能全部删除）、dp[0][j] = j（从空串造出长度为 j 的串，只能全部插入）。按行从左到右填表即可，答案在 dp[m][n]。

procedure editDistance(A[1..m], B[1..n]):
    for i = 0 to m: dp[i][0] = i           // 全部删除
    for j = 0 to n: dp[0][j] = j           // 全部插入
    for i = 1 to m:
        for j = 1 to n:
            del = dp[i-1][j] + 1                 // 删除 A[i]
            ins = dp[i][j-1] + 1                 // 插入 B[j]
            rep = dp[i-1][j-1] + (A[i] == B[j] ? 0 : 1)   // 替换或匹配
            dp[i][j] = min(del, ins, rep)
    return dp[m][n]

// 回溯：从 (m, n) 走回 (0, 0)，每一步记录用到的操作
//   走左上且 A[i] == B[j]  → 该位无需操作
//   走左上且 A[i] != B[j]  → 把 A[i] 替换为 B[j]
//   走上                    → 删除 A[i]
//   走左                    → 插入 B[j]
注意代价不对称

LCS 的表里「上」和「左」是对称的、值只增不减；编辑距离里三个来源都带代价，且 dp 值不再单调，不能简单地用「取较大的那个方向」回溯——必须回到三个候选值里挑出确实达到最小值的那个，否则路径会走不通。

复杂度分析

指标量级说明
最优时间复杂度O(mn)标准填表必须访问全部 m×n 个状态
平均时间复杂度O(mn)每格三次加法与一次取最小值
最坏时间复杂度O(mn)与内容无关；带权版本仍是同阶，只是比较的候选代价不同
空间复杂度O(mn)保留全表用于回溯操作序列；只求距离可滚动到 O(min(m,n))
近似下界O(mn)（猜测）SETH 猜想表明带替换的编辑距离不存在 strongly polynomial 的 O(mn-ε) 算法；只含插入删除时可用 LCS 位并行降到 O(mn/word)
提示：带权版本与退化情形

带权编辑距离：三种操作代价不同（例如替换代价 2、插入删除代价 1，或按字符对给替换代价——生物序列比对里的 PAM/BLOSUM 矩阵即如此），只需把式子里的 +1 换成对应权值，DP 结构不变；此时「替换 = 一次删除 + 一次插入」不再等价，权值必须显式给出。

只允许插入和删除：此时公共部分一定可以保留，最优解形如「删掉 A 中没进 LCS 的字符，再插入 B 中没进 LCS 的字符」，距离 = (m − LCS) + (n − LCS) = m + n − 2·LCS。这个恒等式让「删除式编辑距离」与 LCS 互相归约。

只允许相邻交换就变成了逆序对计数问题（Kendall τ），不再是 DP；三种操作混合且带权时，还可能要用「Damerau 编辑距离」补上「交换相邻两字符」这条第四转移（dp[i][j] = min(dp[i][j], dp[i-2][j-2] + 1)，条件是 A[i]==B[j-1] 且 A[i-1]==B[j]）。

应用与局限

编辑距离最常用在拼写纠错：把词典里每个词与输入词的距离算出来（或用 Levenshtein 自动机在 Trie 上一次遍历），取距离不超过 1~2 的候选；搜索引擎的「您是不是要搜索…」就是它。其次是模糊字符串匹配：在文本 T 中找与模式 P 距离最小的子串，把 DP 的第 0 行设为 0、扫完取最后一列最小值即可，代价 O(|T|·|P|)。在计算生物学里，DNA / 蛋白序列比对（Needleman–Wunsch 全局、Smith–Waterman 局部）是它的加权推广。git、diff3、语音识别的 WFST 打分、乃至 OCR 结果纠正都在用它。

局限：O(mn) 对长序列昂贵，工程上常用带状剪枝（Ukkonen / banded DP，只算 |i-j| ≤ k 的对角带，距离上限 k 时降到 O(k·n)）、或用 min 哈希（MinHash / SimHash）做近似过滤；另外普通编辑距离对「整段移动」这类人类眼中很小的编辑（复制粘贴）度量不佳，需要 LDM（longest common subsequence with move）等扩展。
