完全背包

完全背包（Unbounded / Complete Knapsack）与 0/1 背包只差一个字：每种物品可以选无限多次。别小看这一句差别——它只改动转移方程里的一个下标（从上一行变成本行），也让一维滚动数组的枚举方向从「逆序」变成「正序」。本页用同一张 DP 表把这两处差别演示清楚。

算法原理

设共有 n 种物品，第 i 种重量 w[i]、价值 v[i]，背包容量 W，每种物品供给不限。状态定义为

dp[i][j] = 只允许使用前 i 种物品、容量为 j 时能获得的最大价值。

考虑第 i 种物品拿多少件：要么一件都不拿，问题退化为前 i-1 种；要么至少拿一件，先拿走一件物品 i（占 w[i] 容量、得 v[i] 价值），剩下的容量 j - w[i] 仍然允许继续用前 i 种——这正是与 0/1 背包的分岔点：

dp[i][j] = max( dp[i-1][j], dp[i][j - w[i]] + v[i] )（当 j ≥ w[i]）；否则 dp[i][j] = dp[i-1][j]。

边界是 dp[0][j] = 0：一种物品都不许用，价值恒为 0。0/1 背包的对应式子是 dp[i][j] = max(dp[i-1][j], dp[i-1][j - w[i]] + v[i])，两个来源都在上一行。

procedure completeKnapsack2D(w[1..n], v[1..n], W):
    for j = 0 to W: dp[0][j] = 0            // 边界：没有物品可用
    for i = 1 to n:
        for j = 0 to W:
            dp[i][j] = dp[i-1][j]           // 物品 i 一件都不拿
            if j >= w[i]:
                dp[i][j] = max(dp[i][j], dp[i][j - w[i]] + v[i])
                                            // 拿一件，剩余容量仍可继续拿物品 i
                                            // 注意来源是 dp[i][*]（本行），不是 dp[i-1][*]
    return dp[n][W]

procedure completeKnapsack1D(w[1..n], v[1..n], W):
    dp[0..W] = 0
    for i = 1 to n:
        for j = w[i] to W:                  // 正序！与 0/1 背包唯一的方向差别
            dp[j] = max(dp[j], dp[j - w[i]] + v[i])
    return dp[W]
为什么「正序」就等价于「可以重复选」

一维数组是二维表按行滚动的结果：写第 i 行时，dp[j] 尚未被本行覆盖，代表上一行的 dp[i-1][j]。

  • 逆序枚举 j（0/1 背包）：算 dp[j] 时 dp[j-w[i]] 还没被本行更新，于是它等于 dp[i-1][j-w[i]]——来源行是「上一行」，物品 i 最多进包一次。
  • 正序枚举 j（完全背包）：算 dp[j] 时 dp[j-w[i]] 已经在本行更新过，等于 dp[i][j-w[i]]——它本身可能已经含了若干件物品 i，再加一件即可。这正是二维转移 dp[i][j] = max(dp[i-1][j], dp[i][j-w[i]] + v[i]) 的原地实现。

换个角度理解：正序相当于把「第 i 种物品有无限多个」看成先做「至少选 0 件」再做「至少选 1 件」……每往前推一格就多一件，重复选取被压缩进了一次转移。

复杂度分析

指标量级说明
最优时间复杂度O(nW)状态数 n×(W+1)，每个状态的转移只有 O(1) 个候选（不像多重背包要枚举件数）
平均时间复杂度O(nW)与输入内容无关，两层循环必然跑满
最坏时间复杂度O(nW)同上；若把 W 看作数值而非输入长度，这是伪多项式时间
空间复杂度O(W)一维滚动数组；因为本行会用到本行左侧的值，必须正序枚举 j，不能像 0/1 那样靠逆序省掉行维
方案回溯O(nW) 时间 / O(nW) 空间需要保留整张二维表才能还原每种物品选了几件
提示：三种常见初始化与转移变形

完全背包的框架只改一行，就能覆盖三类题面：

  • 恰好装满：把 dp[0] = 0、其余 dp[j] = -∞（求最大价值时）。含义是「容量 j 只有在被恰好填满时才合法」。转移仍是正序 dp[j] = max(dp[j], dp[j-w]+v)；结束后若 dp[W] 仍为 -∞ 说明无解。求最小代价时初始化为 +∞ 并把 max 换成 min。
  • 最小物品数：把价值全部视为 1（或直接把 +v[i] 写成 +1），初值 dp[0]=0、其余 +∞，转移取 min，正序枚举。dp[W] 即凑出容量 W 所需的最少件数（LeetCode 322 零钱兑换即此形式）。
  • 方案计数：令 dp[j] 为凑出容量 j 的方案数，dp[0] = 1，正序执行 dp[j] += dp[j - w[i]]。注意「物品在外层、容量在内层正序」统计的是组合数（不计顺序）；若把循环交换成「容量在外层」，得到的就是排列数（LeetCode 377/518 的差别正在此处）。

应用与局限

完全背包是「无限供给」问题的标准模型：硬币找零（每种面额不限）、无限次选择的资源分配、把若干种无限供应的原料凑成固定产量、以及不定方程非负整数解的计数。它也是 0/1 背包、多重背包（二进制拆分或单调队列后同样落到 O(nW)）、分组背包的共同骨架，理解了「来源行」的变化，一族背包问题就通了。

局限与所有背包相同：复杂度含 W，属伪多项时间，容量到 10⁹ 量级时 DP 失效，只能转向贪心近似、数学构造或 Meet-in-the-Middle。此外，与 0/1 背包不同，完全背包的最优解里可能出现「某种物品性价比最高，被无限堆叠」的退化结构，此时构造类贪心（按单位价值排序）在某些整除性质成立的数据上是精确的，DP 反而不必要。
