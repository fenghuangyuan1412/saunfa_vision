数字三角形

数字三角形（Number Triangle）是动态规划最经典的入门模型：给定一个由数字组成的三角形，从顶点出发，每一步只能走向左下或右下两个相邻位置，要求走到底行的一条路径，使路径上所有数字之和最大。它足够简单，却包含了一道 DP 题目必须回答的全部六个问题：状态定义、转移方程、边界条件、填表顺序、答案位置、方案回溯。

算法原理

直接用「枚举所有路径」做，深度 n 的三角形共有 2^(n-1) 条路径，指数级不可接受。关键观察是：到达同一个格子的所有路径，之后能拿到的收益与「怎么走到这里」完全无关——只取决于当前位置。于是可以把「位置」作为状态。

六要素速览（自底向上版，本页演示采用）
  • 状态定义：dp[i][j] = 从格子 (i, j) 出发走到底行的最大路径和。
  • 转移方程：dp[i][j] = a[i][j] + max(dp[i+1][j], dp[i+1][j+1])。
  • 边界条件：底行 dp[n-1][j] = a[n-1][j]（下方没有格子，只能取自己）。
  • 填表顺序：按行号 i 从 n-2 递减到 0，每行内 j 从左到右；被依赖的下一行一定已填好。
  • 答案位置：顶点 dp[0][0]。
  • 方案回溯：从 (0, 0) 出发，每步在两个孩子中挑 dp 值较大者，走到底行即得最优路径。

另一种等价的定义是「从顶走到 (i, j) 的最大路径和」，即 dp[i][j] = a[i][j] + max(dp[i-1][j-1], dp[i-1][j])。两种方向都对，但边界与答案位置不同，写代码前必须先确定用哪一种。

自底向上（推荐）

procedure bottomUp(a[0..n-1][0..i], n):
    for j = 0 to n - 1:
        dp[n-1][j] = a[n-1][j]              // 边界：底行到自身
    for i = n - 2 downTo 0:                 // 填表顺序：自底向上
        for j = 0 to i:
            dp[i][j] = a[i][j] + max(dp[i+1][j], dp[i+1][j+1])
    return dp[0][0]                         // 答案在顶点

procedure recoverPath(a, dp, n):            // 方案回溯
    path = [(0, 0)]; j = 0
    for i = 0 to n - 2:
        if dp[i+1][j] >= dp[i+1][j+1]:      // 左下不劣于右下则走左下
            j = j                           //  stays 在同一列
        else:
            j = j + 1                       // 走右下
        path.append((i + 1, j))
    return path

自顶向下

procedure topDown(a, n):
    dp[0][0] = a[0][0]                                   // 边界：顶点
    for i = 1 to n - 1:
        dp[i][0] = a[i][0] + dp[i-1][0]                  // 左边界：只能从正上方来
        for j = 1 to i - 1:
            dp[i][j] = a[i][j] + max(dp[i-1][j-1], dp[i-1][j])
        dp[i][i] = a[i][i] + dp[i-1][i-1]                // 右边界：只能从左上 come
    return max(dp[n-1][0 .. n-1])                        // 答案在底行的最大值
边界为什么要单独写

自顶向下时，第 i 行只有 i+1 个格子：最左侧 j = 0 没有「左上」这个前驱，最右侧 j = i 没有「正上」这个前驱。若直接用统一转移式，会读到不存在的格子（越界或脏数据），这是本题最常见的 WA 来源。自底向上没有这个问题：底行以下没有格子，非底行的每个格子下方必定有两个孩子，因此边界只有一行。

从填表到记忆化搜索

把「自顶向下的递归」加上缓存，就得到记忆化搜索：它和递推在复杂度与状态数上完全等价，但填表顺序由递归自动决定，边界写成递归出口，因而在状态转移方向复杂（如 DAG 上的 DP）时更好写。

memo[0..n-1][0..n-1] = -1                     // 「未计算」标记

function solve(i, j):                          // 从 (i,j) 到底行的最大路径和
    if i == n - 1: return a[i][j]             // 递归出口 = 边界条件
    if memo[i][j] != -1: return memo[i][j]    // 命中缓存，避免重复计算
    memo[i][j] = a[i][j] + max(solve(i+1, j), solve(i+1, j+1))
    return memo[i][j]

answer = solve(0, 0)

注意：没有缓存的递归只是指数级暴力搜索（同一个格子会被成千上万次访问），「递归 + 缓存」才是动态规划。判断一个 DP 是否可行，看状态数 × 转移代价是否卡在时限内。

提示：滚动数组把空间压到 O(n)

自底向上时，第 i 行只依赖第 i+1 行，整个二维 dp 表可以压缩成一行 f[0..n-1]：

for j = 0 to n - 1: f[j] = a[n-1][j]
for i = n - 2 downTo 0:
    for j = 0 to i:
        f[j] = a[i][j] + max(f[j], f[j+1])   // 左下 = 旧的 f[j]，右下 = f[j+1]

因为 j 从小到大更新，读 f[j+1] 时它仍是下一行的旧值，顺序安全（对比 0/1 背包必须逆序：那里的依赖是 f[j - w]，正序会读到本轮刚写的新值）。代价是丢掉整张表后无法直接回溯方案，需要额外记录每步选择，或保留完整的 dp 表。

复杂度分析

指标量级说明
最优时间复杂度O(n²)状态数 n(n+1)/2，每个状态转移 O(1)，与数据无关
平均时间复杂度O(n²)共约 n²/2 个格子，逐格填表
最坏时间复杂度O(n²)不存在退化情况；暴力搜索才是 O(2ⁿ)
空间复杂度O(n²)完整 dp 表；滚动数组优化后 O(n)（见上方提示）
方案回溯O(n)需保留 dp 表；滚动数组下要另存每步选择

应用与局限

数字三角形的价值在于它是所有「网格 / 路径型 DP」的最小骨架：把状态从二维位置推广到「位置 + 额外维度」，就得到带约束的路径问题（例如 最小路径和、三角形中不同路径计数、限制转向次数的行走问题、数塔变体）。它同时也是理解「状态必须覆盖最优子结构」这一要求的最好例子——之所以能用 dp[i][j] 一个数替代「所有到达方式」，是因为后续收益与来路无关（最优子结构 + 无后效性）。

局限：状态转移是 DAG 上单向的，因此本题的「贪心每步取较大孩子」会给出错误答案（局部最优不等于全局最优，DP 之所以要先算出 dp 再回溯正是为此）。当三角形的「宽度」不是行数而是任意图时，模型就升级为一般图上的最短路或树形 DP。
