最长上升子序列

最长上升子序列（Longest Increasing Subsequence，LIS）要求在一个序列中选出尽量多的元素，使它们下标递增且取值严格递增（不要求连续）。它是线性 DP 的代表题，也是「状态定义决定一切」的最好教材：状态定义错一个字，转移就彻底不成立。

算法原理

设序列为 A[0..n-1]。

  • 状态定义：dp[i] = 以 A[i] 结尾的上升子序列的最大长度。「结尾」意味着 A[i] 必须被选中，并且位于子序列末尾。
  • 转移方程：dp[i] = max(dp[j] + 1)，枚举所有 j < i 且 A[j] < A[i]。
  • 边界条件：不存在合法的 j 时 dp[i] = 1（单独一个元素也是长度为 1 的上升子序列）。
  • 填表顺序：i 从小到大；计算 dp[i] 时所有 j < i 已就绪。
  • 答案位置：max(dp[0..n-1])，不是 dp[n-1]——最优子序列未必以最后一个元素结尾。
  • 方案回溯：转移时记录前驱 pre[i] = j，从取到最大值的下标反向走链。
procedure LIS(A[0..n-1]):
    for i = 0 to n - 1:
        dp[i] = 1                                 // 边界：只取 A[i] 自己
        pre[i] = -1
        for j = 0 to i - 1:
            if A[j] < A[i] and dp[j] + 1 > dp[i]: // 严格上升：相等不合法
                dp[i] = dp[j] + 1
                pre[i] = j                        // 记录前驱，便于回溯
    best = 0; pos = 0
    for i = 0 to n - 1:
        if dp[i] > best: best = dp[i]; pos = i   // 答案是 max，而非 dp[n-1]
    return best

procedure recover(pos):                           // 方案回溯（逆序得到再反转）
    while pos != -1:
        emit A[pos]; pos = pre[pos]
易错：把 dp[i] 定义成「前 i 个元素的 LIS 长度」

若定义 dp[i] = 前缀 A[0..i] 的 LIS 长度，则无法写出 dp[i] 与 dp[j] 的转移：前缀的最优子序列末尾是谁并不确定，也就无法判断能否再接上 A[i]。例如 A = [2, 9, 1, 5]，前缀 [2,9] 的 LIS 是 2,9（末尾 9），但 9 > 1 无法接上；而长度同为 2 的另一条子序列并不存在。状态必须携带「末尾元素」这一信息，所以定义成「以 A[i] 结尾」。代价是答案要在所有 i 上取 max。

复杂度分析

指标量级说明
最优时间复杂度O(n²)状态 n 个，每个状态枚举全部 j < i，合计 n(n-1)/2 次判断
平均时间复杂度O(n²)与数据分布无关，都要扫完所有 j
最坏时间复杂度O(n²)同上；贪心 + 二分优化可到 O(n log n)
空间复杂度O(n)dp[] 与 pre[] 各 n 个
回溯方案O(n)沿 pre[] 走链，长度不超过 n
提示：O(n log n) 的贪心 + 二分（耐心排序）

定义 d[x] = 长度为 x 的上升子序列的最小可能末尾元素。可以证明 d[] 随 x 严格递增，因此每来一个 A[i]，用二分找到第一个 ≥ A[i] 的位置 p，令 d[p] = A[i]（若全部 < A[i] 则追加到末尾，长度 +1）。最终 len(d) 就是 LIS 长度。

d = []                                  // d[1..len]，len 即当前答案
for i = 0 to n - 1:
    p = lowerBound(d, A[i])             // 第一个 d[p] >= A[i] 的位置
    if p not found: p = len + 1         // 比所有末尾都大 —— 可以延长
    d[p] = A[i]
answer = len

以 A = [2, 5, 3, 7, 1, 6] 为例逐步维护（每行处理一个元素，粗体为本轮被改写的位置）：

处理 xd[1..len]（长度 1 / 2 / 3 的最小末尾）操作与原因
2[2]，len = 1空表，直接建立长度 1 的末尾
5[2, 5]，len = 25 大于所有 d，追加：得到 2, 5
3[2, 3]，len = 2第一个 ≥ 3 的是 d[2] = 5，改为 3（长度 2 的末尾更小更优）
7[2, 3, 7]，len = 3追加，得到 2, 3, 7
1[1, 3, 7]，len = 3改写 d[1]：长度 1 的末尾只需 1，未来更容易延长
6[1, 3, 6]，len = 3改写 d[3]：7 → 6

注意 d[] 本身通常不是原序列的子序列（结束时 [1,3,6] 中 1 出现在 3 之后），但它的长度一定等于 LIS 长度：len 只在遇到能延长的元素时才 +1，且长度 k 的上升子序列确实存在（归纳可证）。要输出方案仍需配合下标记录，或用 O(n²) 的 dp[] + 前驱回溯。

应用与局限

LIS 是偏序集上的经典问题：把下标与取值合成二维点对 (i, A[i])，「i < j 且 A[i] < A[j]」就是一个二维偏序关系，LIS 即该偏序集里的最长链。由此引出两个重要结论：

  • Dilworth 定理：有限偏序集的最小反链划分数 = 最长链长度。落到序列上，「把序列划分为尽量少的下降子序列」的最少数恰好等于 LIS 长度（这也是「 patience sorting / 耐心排序」的贪心正确性来源）。
  • 二维偏序：把 LIS 的「下标 + 取值」换成任意两维，就得到 俄罗斯套娃信封（先按一维排序、再在另一维上求 LIS）、最多不重叠线段、CDQ 分治与树状数组优化 DP 等问题族。当数据范围达到 n ≈ 10⁵~10⁶ 时，O(n²) 会超时，必须换成二分或树状数组版本。

局限：LIS 只能处理「一维顺序 + 一维大小」的约束；若子序列还要满足第三种约束（例如颜色交替、和为定值），状态就需要增加维度，退化为 O(n² · 附加维度) 的 DP。此外它不满足贪心——每步取最小末尾的朴素贪心并不给出最优解，必须用 d[] 的耐心排序技巧才行。
