二分查找

二分查找（Binary Search）是在有序数组上定位目标值的基础算法。它每次都考察区间中点：若中点元素等于目标则结束；否则根据比较结果把搜索区间 halve（折半），丢掉不可能包含答案的一半。查找过程构成一条清晰的循环不变量。

算法原理

设数组 A 升序且无重复元素，维护闭区间 [lo, hi] 表示「若目标存在，必在此区间内」。初始 lo = 0，hi = n-1。每一轮取 mid = (lo + hi) >> 1，比较 A[mid] 与目标 t：

  • A[mid] == t：命中，返回 mid；
  • A[mid] < t：目标只可能在右侧，收缩为 [mid+1, hi]，即 lo = mid + 1；
  • A[mid] > t：目标只可能在左侧，收缩为 [lo, mid-1]，即 hi = mid - 1。

循环不变量：进入每一轮时，若目标存在于数组，则它一定落在当前闭区间 [lo, hi] 内。初始化时区间为全数组，显然成立；上面三种收缩都只剔除「比较过且确定不等于目标」或「由单调性排除」的下标，不变量得以保持。循环终止有两种情况：命中返回；或 lo > hi 区间变空——由不变量可知目标必然不存在，返回未找到。

function binarySearch(A[0..n-1], t):   // A 升序、无重复
    lo = 0, hi = n - 1
    while lo <= hi:
        mid = (lo + hi) >> 1
        if A[mid] == t:
            return mid          // 命中
        else if A[mid] < t:
            lo = mid + 1        // 排除 [lo, mid]
        else:
            hi = mid - 1        // 排除 [mid, hi]
    return -1                   // 区间为空，未找到

区间每轮至少折半，比较次数不超过 ⌈log₂(n+1)⌉ 次。

注意：mid 溢出与边界坑

1. mid 溢出。在 C++/Java 等定宽整型下，mid = (lo + hi) / 2 当 lo + hi 超过 INT_MAX 时会溢出为负数。标准写法是 mid = lo + ((hi - lo) >> 1)：先作差再折半，结果不变但中间值不会溢出。JavaScript 的数字有 53 位整数精度，常规规模下无碍，但这个写法习惯应当保留。

2. 「查找第一个 / 最后一个」的边界坑。当数组允许重复、要求返回第一个（最后一个）等于目标的位置时，命中后不能立即返回：找第一个应在命中后仍向左收缩 hi = mid - 1 并记录候选；找最后一个则向右收缩 lo = mid + 1。若改写成 while lo < hi 配合 hi = mid 的「左闭右开/半开区间」模板，则必须保证 mid 取整方向与收缩方向匹配（否则 lo == hi 时 mid = (lo+hi)>>1 恒等于 lo，区间不再缩小，产生死循环）。核心心法：选定一套区间语义（本页用闭区间 [lo, hi]），初始化、循环条件、两处收缩必须整体自洽，不可混用。

复杂度分析

指标量级说明
最优时间复杂度O(1)第一轮 mid 恰好命中
平均时间复杂度O(log n)区间每轮折半，约 log₂n 次比较
最坏时间复杂度O(log n)未找到时收缩到区间为空，仍为 ⌈log₂(n+1)⌉ 轮
空间复杂度O(1)迭代版仅用 lo/hi/mid 三个变量（递归版为 O(log n) 调用栈）

应用与局限

二分查找是「有序性 ⇒ 折半排除」这一思想的原型：在旋转有序数组中查找目标时，mid 至少有一侧保持有序，可先判断落点侧再收缩；二分答案则把「求最小/最大的满足某单调性质的值」化为对答案区间的判定，不要求数据本身可随机访问，只要求判定函数单调（详见 OI Wiki 二分页）。局限：前提是数据有序且支持随机访问；对需要频繁插拔的集合，维护有序数组的代价高，一般改用平衡树或哈希结构。另外二分对缓存友好性不如线性扫描，小规模数据（n < 64 左右）时 std::lower_bound 未必比手工线性快。
