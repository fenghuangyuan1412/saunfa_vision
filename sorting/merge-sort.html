归并排序

归并排序（Merge Sort）是一种基于分治思想的比较排序算法。它把区间递归地一分为二，直到每个区间只剩 1 个元素（天然有序），再自底向上把两个有序段合并成一个更长的有序段。因为合并过程可以刻意保持相等元素的先后次序，归并排序是稳定排序，且所有情况下的时间复杂度都稳定在 O(n log n)。

算法原理

整个算法由两部分组成：

  • 拆分（分治）：sortSeg(A, lo, hi) 取 mid = ⌊(lo + hi) / 2⌋，先递归排序左半 [lo, mid]，再递归排序右半 [mid+1, hi]。区间长度为 1 时递归终止。
  • 合并：两个子段都已有序，用两个游标 i、j 分别指向左右两段的开头，每次比较 A[i] 与 A[j]，把较小者写入临时数组 tmp 并让对应游标右移；相等时取左段，这正是稳定性的来源。一段取空后，把另一段的剩余元素整段搬入 tmp。最后把 tmp 逐个写回 A[lo .. hi]。

注意：某一段「段内有序」并不意味着其中元素已经到达最终位置，它还要参与上一层的合并。因此本页只在最后一步才把所有条形标绿。

procedure mergeSort(A[0..n-1]):
    sortSeg(A, 0, n - 1)

procedure sortSeg(A, lo, hi):
    if lo == hi: return                 // 只剩 1 个元素，天然有序
    mid = (lo + hi) / 2                 // 向下取整
    sortSeg(A, lo, mid)                 // 递归排序左半
    sortSeg(A, mid + 1, hi)             // 递归排序右半
    merge(A, lo, mid, hi)               // 合并两个有序段

procedure merge(A, lo, mid, hi):
    tp = 0
    i = lo                              // 左段游标
    j = mid + 1                         // 右段游标
    while i <= mid and j <= hi:
        if A[i] <= A[j]:                // 相等取左 —— 稳定性的关键
            tmp[tp] = A[i]; i = i + 1
        else:
            tmp[tp] = A[j]; j = j + 1
        tp = tp + 1
    while i <= mid: tmp[tp] = A[i]; i += 1; tp += 1   // 左段剩余
    while j <= hi:  tmp[tp] = A[j]; j += 1; tp += 1   // 右段剩余
    for k = lo to hi:                   // 把临时数组写回主数组
        A[k] = tmp[k - lo]
为什么需要临时数组

合并必须同时保留左右两段的原始次序，直接写回 A 会覆盖尚未取出的元素，因此需要长度不超过 n 的辅助空间。这也是归并排序 O(n) 额外空间的来源。

复杂度分析

指标量级说明
最优时间复杂度O(n log n)递归树恒为 log n 层，每层合并合计 O(n)，与输入无关
平均时间复杂度O(n log n)递归树共 ⌈log₂ n⌉ 层，每层合并总工作量 O(n)，比较次数约为 n log₂ n 量级
最坏时间复杂度O(n log n)划分与数据分布无关，不存在退化情况
空间复杂度O(n)临时数组 tmp 最长为 n，另有 O(log n) 递归栈
稳定性稳定合并时 A[i] ≤ A[j] 优先取左段，相等元素相对次序不变
提示：稳定性与「零额外空间」的链表变种

归并排序是比较排序中少数天然稳定的 O(n log n) 算法：只要合并时「相等取左」，稳定性能一路向上传递。需要稳定且能接受 O(n) 空间时，它是首选（快速排序不稳定）。

把待排序对象放进单向链表，归并排序的额外空间可以降到 O(1)：合并两条有序链表只需改动指针，不需要数组式临时缓冲；找中点用快慢指针，因此递归栈也仅是 log n 层，改写为自底向上的迭代合并后连栈都可省掉（LeetCode 148「排序链表」即此变种）。相反，数组上的归并不可能原地高效完成——若要原地合并，代价会退化到 O(n log n) 次旋转操作。

工程实现常做两点优化：① 小区间（约 8~16 个元素）切换到插入排序；② 合并前先判 A[mid] ≤ A[mid+1]，已有序则跳过本次合并，这使最优情况降为 O(n)（即 Timsort 的思路之一）。

应用与局限

归并排序的性能保证与稳定性使它成为外部排序的主力：数据放不进内存时，先分段排序写回磁盘，再多路归并合并，总 I/O 量约为 O(n log n) 量级的分块扫描。它也用于求逆序对个数——合并时统计「右段元素被提前取走」的次数即可在 O(n log n) 内得到答案。要求稳定、或数据以链表/文件形式存在时，归并排序往往是唯一合理选择；STL 的 stable_sort 就是归并排序（内存不足时退化为内部块合并）。

局限在于 O(n) 的辅助空间：对内存受限或元素巨大的场景不友好；数组版本的写入次数约为 n log n，缓存局部性不如快速排序，因此在纯内存、不要求稳定的通用排序中通常慢于快速排序。
