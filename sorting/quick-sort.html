快速排序

快速排序（Quick Sort）是一种基于分治思想的比较排序算法。它从区间中选取一个元素作为枢轴（pivot），把区间划分为「不大于枢轴」与「大于枢轴」两部分，然后对两部分递归地执行同样的操作。因为划分是原地完成的，且访问模式对缓存友好，快速排序是实践中最常用的通用排序算法之一。

算法原理

本页采用经典的 Lomuto 分区方案：取区间最右元素 A[hi] 作为枢轴，用两个指针维护不变量。

  • 不变量：A[lo .. i] 全部 ≤ pivot，A[i+1 .. j-1] 全部 > pivot，A[hi] 是暂存的枢轴。
  • 扫描指针 j 从 lo 走到 hi-1：若 A[j] ≤ pivot，先令 i 前进，再交换 A[i] 与 A[j]，把小元素并入左侧区；否则什么也不做，j 继续右移。
  • 扫描结束后，A[i+1] 就是左侧区之后第一个大于枢轴的位置，交换 A[i+1] 与 A[hi]，枢轴即落在最终位置 p = i+1 上。
  • 对 [lo, p-1] 与 [p+1, hi] 递归排序；区间长度不超过 1 时递归终止。
procedure quickSort(A, lo, hi):     // 对 A[lo..hi] 排序
    if lo < hi:
        p = partition(A, lo, hi)        // Lomuto 分区，返回枢轴最终位置
        quickSort(A, lo, p - 1)         // 递归排序左半
        quickSort(A, p + 1, hi)         // 递归排序右半

procedure partition(A, lo, hi):
    pivot = A[hi]                   // 取区间最右元素为枢轴
    i = lo - 1                      // A[lo..i] 恒 <= pivot
    for j = lo to hi - 1:
        if A[j] <= pivot:
            i = i + 1
            swap(A[i], A[j])        // 把小元素换进左侧区
    swap(A[i + 1], A[hi])           // 枢轴归位
    return i + 1
一次分区示例

区间 [2, 9]，枢轴 pivot = A[9] = 45。扫描中若 A[5] = 62，因为 62 > 45，不交换，j 直接右移；若 A[7] = 30，因为 30 ≤ 45，i 前进后交换 A[i] 与 A[7]。扫描完成后把 A[i+1] 与 A[9] 交换，45 就位，其左侧都不大于它、右侧都严格大于它。

复杂度分析

指标量级说明
最优时间复杂度O(n log n)每次划分都接近对半分，递归树共 log n 层，每层合计 O(n)
平均时间复杂度O(n log n)期望约 1.39 n log n 次比较，常数因子小、缓存友好
最坏时间复杂度O(n²)触发条件：每次枢轴都取到端序（区间已有序或逆序、大量重复元素且固定取最右），划分为 n 与 0，递归退化为 n 层，每层扫描 O(n)
空间复杂度O(log n)原地排序，仅需递归调用栈，期望深度 O(log n)；最坏退化时递归栈为 O(n)
稳定性不稳定枢轴归位的远距离交换会打乱相等元素的相对顺序
警告：最坏情况与随机化优化

本页演示固定取 A[hi] 为枢轴，面对已经有序或近似有序的数据会退化为 O(n²)，递归深度也会达到 O(n)，在极端数据下可能爆栈。常见对策：

  • 随机选枢轴：随机取 A[k] 并与 A[hi] 交换后照常分区（随机化快速排序），使期望复杂度稳定在 O(n log n)，且与输入无关。
  • 三数取中（median-of-three）：取 lo、mid、hi 的中位数作枢轴，廉价地避开端序，同时缓解重复元素问题。
  • 双路 / 三路划分：Hoare 双路划分或对含大量重复键使用三路划分（荷兰国旗问题），把等于枢轴的元素集中处理。
  • 内省排序（introsort）：递归深度超过 2 log n 时切换到堆排序，从而保证 O(n log n)；STL 的 sort、Java 部分实现都采用这种策略，并在小区间改用插入排序。

应用与局限

快速排序是多数标准库的默认排序核心（常与插入排序、堆排序组合成内省排序），也是外排序与并行排序的基础构件。它的划分操作还衍生出一个重要算法：快速选择（Quickselect）。求第 k 小的元素时，只需在划分后递归进入包含目标的那一侧，期望复杂度为 O(n)；C++ 的 nth_element 正是基于此实现，常用于求中位数、Top-k 等问题——OI 中「不允许排序，只能 O(n) 求第 k 小」的约束常常暗示使用 nth_element。

局限主要有三点：最坏情况 O(n²)（可用随机化或内省排序规避）；不稳定，需要稳定排序时应选归并排序或基数排序；递归实现有栈开销，对栈深度受限的环境需改写为显式栈。
