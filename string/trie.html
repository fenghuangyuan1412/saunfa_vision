Trie 字典树

Trie（音同「try」，又称字典树、前缀树）把集合里的每个字符串拆成字符，沿一条从根出发的路径存放：根到某个「结束标记」结点的路径上，各条边标注的字符依次拼起来就是一个词。所有共享前缀的词自动共享路径前缀，于是「查找一个词」「统计一个前缀被多少个词覆盖」都只需沿着路径走一次，时间正比于字符串长度，而与字典里有多少词无关。

算法原理

形式定义：Trie 是一棵以字符串为边权的有根树。根结点 root 代表空串；若结点 x 对应字符串 s，则它的子结点 child[x][c] 对应字符串 s + c。结点上的标记 terminal 为真表示「从根走到这里恰好拼成字典中的一个词」。注意 terminal 必须是布尔标记而不是「结点有没有儿子」——一个词可能同时是另一个更长词的前缀（例如 app 与 apple）。

结点里存什么：

  • child[Σ]：指向子结点的指针（或数组下标），按字符直接定位，因此下行一趟不需要比较；
  • terminal：结束标记，区分「是一个词」与「只是某个词的前缀」；
  • cnt：经过计数——插入时有多少个词经过该结点。根结点的 cnt 就是字典规模，结点 x 的 cnt 等于「以 x 的路径字符串为前缀的词数」。有了它，前缀统计从 O(Σ长度) 的搜索变成 O(L) 的一次读取。
struct Node:
    child[0..25]       // 子结点指针，初值 nil；child[c] 表示往下拼一个字符 c
    cnt                // 经过计数：有多少个词的路径经过本结点
    terminal           // 结束标记：是否有词恰好在此结束

procedure insert(word w):
    x = root
    x.cnt = x.cnt + 1
    for k = 0 .. |w|-1:
        c = w[k]
        if x.child[c] = nil:            // 该字符分支不存在
            x.child[c] = new Node()     // 现场新建一个结点
        x = x.child[c]
        x.cnt = x.cnt + 1
    x.terminal = true                   // 打上结束标记

function query(word w):                 // w 是否是字典中的一个完整词
    x = root
    for k = 0 .. |w|-1:
        c = w[k]
        if x.child[c] = nil:
            return NOT_FOUND            // 走到缺失分支，前缀都不存在
        x = x.child[c]
    if x.terminal: return FOUND         // 走通且有结束标记
    else: return PREFIX_ONLY            // 只是别的词的前缀

function countPrefix(word p):           // 以 p 为前缀的词有多少个
    x = root
    for k = 0 .. |p|-1:
        if x.child[p[k]] = nil: return 0
        x = x.child[p[k]]
    return x.cnt

复杂度从哪来：插入、查询、前缀统计都只是沿边走 L 步，每步一次数组下标访问，因此都是 O(L)，与字典中词的个数 n 无关。这一点和哈希表不同：哈希表判定「串是否等于某个词」平均 O(L)（要算哈希并处理冲突），但它天生无法回答「以 ap 开头的词有几个」——那需要枚举全部 n 个词。

与其他结构的对比：

  • 哈希表：整词查询同为线性时间，常数更小、实现更省事；但不支持前缀查询、不支持有序遍历，且哈希函数本身要读完整串。
  • 二叉搜索树 / 平衡树：有序、能求前驱后继，但一次比较字符串就要 O(L)，整趟查找是 O(L log n)；Trie 的下行不做字符串比较，是 O(L)。
  • Trie：前缀信息天然可见，最长公共前缀、按字典序枚举（DFS 即有序）都是顺手的事。

空间开销与压缩：朴素上界是 O(n · |Σ|)（n 个结点、每结点 |Σ| 条边），但实际存储的非零边只有 Σ|w| - 共享前缀长度 那么多，所以真实占用是「所有边的字符数」级别；用 map 或「儿子-兄弟」链式存边可以进一步省下空指针。当字符集很大（如 0/1 串、整数二进制位）时，把「只有一条儿子的链」合并成一条带字符串边权的边，就得到压缩 Trie（Radix Tree / Patricia Trie），结点数从「字符总数」降到「词数」量级。

注意：Trie 的三处常见坑

1. 结束标记不可省。只用「结点是否存在」来判定命中，会把 app 误判为字典词（其实只存在 apple），也会把「前缀命中」与「整词命中」混为一谈。本页演示中查询会明确区分 命中 / 只作为前缀存在 / 分支缺失 三种结论。

2. 结点编号 ≠ 字符串顺序。结点编号只是分配顺序（本页图中结点下方标注 #id，圈内数字是 cnt）。要看字典序，必须对子边按字符排序后 DFS，而不是按编号遍历。

3. 重复插入。若把同一个词插入两次，cnt 会变成 2，前缀统计会翻倍。本页的演示按「集合」处理：已存在的词不会重复登记 cnt；若要支持重复词，应改用 endTimes（结束次数）而不是布尔标记。

复杂度分析

记字典中词的个数为 n，字符串总字符数（所有词长度之和）为 S，单次操作的串长为 L，字符集大小为 |Σ|。

指标量级说明
插入时间（最优/平均/最坏）O(L)沿路径下行 L 步，与 n 无关；至多新建 L 个结点
查询时间（最优/平均/最坏）O(L)最坏走满 L 步；缺失分支可能提前结束，更省
前缀统计时间O(L)下行到前缀末端结点后读 cnt，O(1) 出答案
字典序枚举全部词O(S)按字符顺序 DFS，每个字符访问一次
空间复杂度O(n · |Σ|)（上界）实际只占已用边数 O(S)：结点数 ≤ S+1，非零边数 = 结点数 − 1。压缩 Trie 可把结点降到 O(n)
稳定性 / 是否有序无「稳定性」概念；天然支持字典序与前序剪枝

应用与局限

应用：① 字典查询与拼写检查、自动补全（沿前缀下行后 DFS 出所有词）；② 前缀匹配 / 通配前缀统计，如 IP 路由表的最长前缀匹配；③ 01-Trie：把整数按二进制位从高到低插入只有 0/1 两条边的 Trie，查询「与 x 异或值最大/最小的数」时贪心地走相反位，单次 O(位宽)——这是「最大异或对」一类题的标准解法；④ AC 自动机：在 Trie 上补一组失败指针（等价于把 KMP 的 next 推广到多模式串），即可一次扫描匹配所有模式串；⑤ 可持久化 Trie：对每个前缀版本做路径复制，可回答「区间 [l, r] 内与 x 异或最大值」。

局限：空间随字符总数与字符集大小膨胀，英文小写还好，汉字或 Unicode 全字符集必须换压缩 Trie 或哈希；不支持「删除后精确回收结点」（删词要沿路减 cnt，再自底向上剪掉 cnt = 0 且非词尾的结点）；无法处理「通配符在中间」的模糊查询（那需要后缀树 / 后缀数组，见 OI Wiki 后缀数组）。
