KMP 模式匹配

给定主串 T（长 n）与模式串 P（长 m），要在 T 中找出 P 出现的位置。朴素匹配每换一个对齐起点就把 P 从头比起，主串指针反复回退，最坏 O(nm)。KMP 的关键洞察是：失配那一刻，主串里刚刚比过的那一段我们已经知道了，用它和模式串自身的重叠信息就能一步跳到正确的对齐，主串指针 i 全程只前进、绝不回退，于是总比较次数降到线性。

算法原理

一、朴素匹配慢在哪里

procedure naive(T[0..n-1], P[0..m-1]):
    for s = 0 .. n-m:              // s 是模式串对齐的起点
        for j = 0 .. m-1:
            if T[s+j] ≠ P[j]: break        // 失配，起点 s 被否掉
        // 下一个起点 s+1 又从 T[s+1] 开始比，T[s+1..s+j] 这段白白重看一遍

设想 T = "aaaaab..."、P = "aaaac"：每次都要比到第 5 个字符才发现不等，然后前功尽弃，比较次数达到 Θ(nm)。浪费的根源是主串指针回退——它把已获得的信息丢掉了。

二、前缀函数 / next 数组

本页采用「前缀长度」下标约定，并在全页保持一致：

本页的定义

next[k] = 字符串 P 的前 k 个字符组成的前缀 P[0..k-1] 的最长「真前缀 = 真后缀」的长度（真前缀 / 真后缀指不包括整串自己，空串算，长度下界为 0）。k 的取值范围是 0..m：把 k 理解为「当前已经匹配了 k 个字符」，那么失配时把 j 跳到 next[j] 就是本页全部用途。next[0] = 0 只是哨兵，表示一个字符都没匹配上、无处可退。

按这个定义，对 P = "abab"：next[0]=0（哨兵）、next[1]=0（"a" 无非空真前缀）、next[2]=0（"ab"）、next[3]=1（"aba" 的真前缀 "a" = 真后缀 "a"）、next[4]=2（"abab" 的 "ab" = "ab"）。

三、求 next：把自己和自己做一次 KMP

procedure buildNext(P[0..m-1]):
    next[0] = 0                     // 哨兵
    next[1] = 0                     // 长度 1 的前缀没有非空真前缀
    i = 2
    while i <= m:
        j = next[i - 1]             // 候选长度：前一格的答案
        while j > 0 且 P[j] ≠ P[i - 1]:
            j = next[j]             // 候选不够长，继续缩短
        if P[j] == P[i - 1]:
            j = j + 1               // 能在候选后面再接一个字符
        next[i] = j
        i = i + 1

正确性：next[i-1] = j 意味着 P[0..j-1] = P[i-1-j..i-2]。若再有 P[j] = P[i-1]，就在两端各接一个字符，得到 P[0..j] = P[i-1-j..i-1]，即 next[i] ≥ j+1；而 next[i] 不可能超过 j+1（否则去掉最后一位就给出 next[i-1] ≥ j+1，矛盾）。若 P[j] ≠ P[i-1]，则长度 j+1 不成立，退而求其次考察 next[j]——所有比 j 短的候选都被这条链覆盖，一个不漏。

四、匹配

procedure kmpSearch(T[0..n-1], P[0..m-1]):
    buildNext(P)                    // O(m)
    i = 0, j = 0                    // i：主串指针（永不回退）；j：已匹配的模式串长度
    while i < n:
        if T[i] == P[j]:            // 注意 j < m 恒成立，见下
            i = i + 1; j = j + 1    // 双双前进，对齐起点 i - j 不变
        else if j > 0:
            j = next[j]             // 失配：j 回退，i 不动 —— 模式串相对主串右滑
        else:
            i = i + 1               // j = 0 无处可退，主串指针前移
        if j == m:
            report 一次命中，起点 = i - m
            j = next[m]             // 回退后继续找下一个（允许重叠）出现位置

失配回退为什么正确：此刻已匹配 j 个字符，即 P[0..j-1] = T[i-j..i-1]。新的对齐起点若落在 s = i - k（即希望保持 k 个已匹配字符），就必须有 P[0..k-1] = P[j-k..j-1]，也就是 k 是前缀 P[0..j-1] 的一个「真前缀 = 真后缀」的长度。取最大的这类 k = next[j] 即可：任何 next[j] < k < j 都不满足等式，那一格必然立刻失配，跳过它们不会漏解；而更小的 k 将来还能通过 next 链继续取到。因为 j == m 时立即被报告并回退成 next[m] < m，循环开头总有 j < m，故 P[j] 合法。

提示：next 数组有两套下标约定，抄代码前先对齐

本页约定（0 初始 / 前缀长度）：next[0] = 0、next[1] = 0，next 长 m+1，j 表示「已匹配字符数」，失配时 j = next[j]，且必须额外处理「j = 0 时 i++」。

另一种常见约定（−1 初始 / 字符下标）：next[0] = -1，j 表示「下一次要比较的模式串下标」，写成统一分支：

i = 0, j = -1
while i < n:
    if j == -1 或 T[i] == P[j]:  i++; j++       // 哨兵 -1 让 i 自动前移
    else:  j = next[j]

此时 next[i] 的含义是「P[0..i-1] 的最长公共前后缀长度」再往前挪一格，两套值不能互换使用。两套写法都对，混用（例如拿 -1 约定求出的表喂给 0 约定的匹配循环，或忘记 j == 0 时 i 要前移）是 KMP 最常见的 bug 来源。本题可视化里 next 行的格子标注了自己的下标 k，请对照本页定义阅读。

找所有出现位置与找第一个的差别只在一处：报告命中后不退出，而是令 j = next[m] 继续。若题目要求不允许重叠，命中后直接把 j 置 0（并把 i 移到 i）即可。

复杂度分析

记主串长 n、模式串长 m。

指标最优平均最坏说明
预处理（求 next）时间O(m)O(m)O(m)i 递增 m 次；j 每轮至多 +1，回退总次数 ≤ m，摊还线性
匹配时间O(n)O(n)O(n)命中可出现 O(n) 次；比较次数 < 2n（i 单调，j 只增不减地摊还）
总时间O(n+m)O(n+m)O(n+m)对比朴素的最坏 O(nm)，如 T = a^n、P = a^{m-1}b
空间复杂度O(m)只额外存 next[0..m]；匹配本身 O(1)
稳定性 / 是否原地无稳定性概念；单趟扫描、原地推进，适合流式（在线）匹配

应用与局限

应用：KMP 的前缀函数不只能做匹配——最小循环节长度是 m - next[m]（当 m 是它的倍数时）；「字符串周期 / border 计数」「把 T + '#' + P 当一个串求前缀函数，得到 P 的每个前缀在 T 中的最长匹配」都是同一套工具；把 fail 指针串起来还得到 fail 树，可离线回答前缀嵌套问题。

局限：① KMP 假定主串固定、只改动模式串；若主串要频繁插入/删除（可修改文本），线性匹配的前提不成立，应改用后缀树 / 后缀数组或动态字符串结构。② next 只描述「前缀 = 后缀」，无法处理带通配符、编辑距离类匹配，那需要 Z 函数（扩展 KMP，z[i] = T[i..] 与 T 的最长公共前缀，同样 O(n)，在「对齐点信息」上比 next 更直观）或 FFT / 自动机方法。③ 多个模式串同时匹配时，逐条跑 KMP 是 O(k(n+m))，正确做法是把所有模式串建成 Trie 再补 fail 指针，即 AC 自动机——可以视作「多模式串上的 KMP」，一次 O(n + Σm + 命中数)。
