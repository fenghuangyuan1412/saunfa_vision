栈

栈（Stack）是一种只允许在一端进行插入和删除的线性表。这一端称为栈顶（top），另一端称为栈底（bottom）。最后进入栈的元素最先被弹出，因此栈是后进先出（LIFO, Last In First Out）结构。

算法原理

栈的三个核心操作都只作用于栈顶，语义如下：

  • push(x)：把 x 放到栈顶，成为新的栈顶元素；
  • pop()：移除并返回栈顶元素；栈为空时执行 pop 是越界错误（下溢，underflow），必须显式处理；
  • peek()/top()：只读取栈顶元素，不改变栈的状态；空栈同样无值可读。

用数组 s[0..cap-1] 模拟栈时，用一个整型 top 记录栈内元素个数（也即下一个入栈位置），全部操作只需一次赋值或加减：

procedure push(x):
    if top == cap: error "栈满（本演示上限 12）"
    s[top] = x
    top = top + 1

procedure pop():
    if top == 0: error "空栈弹出（underflow）"   // 必须判空
    top = top - 1
    return s[top]

function peek():
    if top == 0: error "空栈无栈顶"
    return s[top - 1]

本页的可视化把栈横向绘制：左侧是栈底，新元素从右侧（也就是栈顶方向）不断生长；栈顶格用蓝色标注「栈顶 top」。

提示：栈与递归

栈之所以重要，是因为函数调用本身就压在一个系统栈上：每次调用把返回地址与局部变量压栈，返回时弹栈——这解释了递归深度过大时的「栈溢出（stack overflow）」，也解释了许多递归算法可以改写成「显式栈 + 循环」的非递归实现。经典应用还包括：表达式求值（算符优先 / 调度场算法，操作数栈与运算符栈配合）、括号匹配（遇左括号入栈、遇右括号弹栈配对，结束时栈空才合法）。

应用与局限

栈的应用非常固定：括号匹配与表达式求值、函数调用与回溯（DFS 的显式实现）、浏览器前进后退、撤销操作、单调栈（在 O(n) 内求每个元素左右第一个更大/更小者，如柱状图最大矩形、接雨水，见 OI Wiki 单调栈）。局限也很明显：LIFO 意味着只能经济地访问最近的一个元素，想读栈底就必须全部弹出；需要按任意位置访问或 FIFO 时，应改用数组或队列（OI Wiki STL stack 提供了竞赛中的一般用法，注意它不支持遍历）。
