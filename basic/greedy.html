贪心

贪心（Greedy）在每一步都取当前看起来最优的选择（局部最优），一旦做出选择就不再回退，期望由此得到全局最优解。它比动态规划更轻量——不需要记录所有子问题——但代价是只有满足特定性质的问题才能用贪心。

算法原理

贪心正确性依赖两个前提：

  • 贪心选择性：存在某个局部最优选择，使得做出该选择之后仍能到达全局最优解（即第一步就能「定下来」）。
  • 最优子结构：问题的最优解包含其子问题的最优解。做完选择后剩下的子问题与原问题同类型。

如何证明贪心是对的——交换论证（exchange argument）：设贪心解为 G = g₁g₂…gₖ，最优解为 O = o₁o₂…oₖ。若二者不同，取第一个不同的位置 i，证明把 oᵢ 替换为 gᵢ 后解依然合法且不变差（因为 gᵢ 是按规则选出的「最早结束 / 最划算」的那个，替换不会占用更多资源）。反复替换可把 O 逐步变成 G，且价值不减，故贪心解最优。

经典例子：活动选择 / 区间调度。给定 n 个区间 [start, end)（同一时间只能进行一个活动），求最多能选出的两两不重叠的区间个数。贪心策略：按结束时间升序排序，依次考察，只要与上一个已选区间不冲突就选它。直觉是「越早结束的活动给后面留出的时间越多」。形式化：设贪心首个选中的是结束最早的区间 g，任一最优解中最先结束的活动为 o，把 o 换成 g 不会与 o 之后的活动冲突（因为 end(g) ≤ start(o) 之后仍成立），故存在包含 g 的最优解，递归下去即得证。

function activitySelection(intervals[1..n]):    // 区间为 [start, end)
    sort intervals by end ascending (tie: start descending)
    chosen = [], lastEnd = -infinity
    for i = 1 to n:
        if intervals[i].start >= lastEnd:       // 与上一个已选区间不冲突
            chosen.append(intervals[i])
            lastEnd = intervals[i].end          // 贪心：一旦选定不回退
    return chosen
提示：贪心 vs 动态规划

贪心是 DP 的「退化特例」：DP 在转移时要枚举所有可能并取最优，贪心则在每一步直接锁定一个选择。判断能否贪心最快的方法是造小反例：写几个极端规模的手工实例，看贪心结果与暴力枚举结果是否一致。

复杂度分析

指标量级说明
最优时间复杂度O(n log n)瓶颈始终在按结束时间排序
平均时间复杂度O(n log n)排序 O(n log n) + 一次线性扫描 O(n)
最坏时间复杂度O(n log n)若输入已按结束时间有序，可用线性插入排序式优化，但比较模型下仍为 O(n log n)
空间复杂度O(n)存放排序后的区间与答案；原地排序时为 O(log n) 栈空间
注意：贪心会失败的例子（0/1 背包按密度）

「每步取单位价值最高」在 0/1 背包 上并不最优。背包容量 50，三个物品：A（重 10，值 60，密度 6.0）、B（重 20，值 100，密度 5.0）、C（重 30，值 120，密度 4.0）。按密度贪心先取 A（已用 10），再取 B（已用 30），此时剩容量 20 装不下 C，得 60 + 100 = 160。而正确最优解是取 B + C：重量 20 + 30 = 50 恰好装满，价值 100 + 120 = 220 > 160。原因：贪心选择「密度最高」并不能保证剩余容量被有效利用，问题缺少「局部最优可延伸到全局最优」的贪心选择性。此时应使用动态规划（见 0/1 背包）；只有分数背包（可切开物品）按密度贪心才正确。

应用与局限

常见贪心模型：区间调度（本页，按右端点）、区间染色 / 最少教室（按左端点扫描 + 优先队列维护结束时间）、Huffman 编码（每次合并权值最小的两棵树，用优先队列实现，O(n log n)）、最小生成树 Kruskal / Prim（每次取不成环的最小边）、最短路 Dijkstra（每次取暂定距离最小的点）、任务调度、各类「字典序最小」构造（如单调栈移除 k 个数字）。

局限：贪心不可回退，正确性强依赖问题结构，通常需要交换论证或拟阵理论保证。判错时的典型症状是「前面吃掉资源导致后面更优组合无法凑成」，如上述 0/1 背包。经验做法：先猜贪心策略，再用小数据暴力对拍验证；一旦找到反例就退回动态规划或搜索。
