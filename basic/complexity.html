复杂度分析

编写算法时最重要的问题之一是：当输入规模 n 增大时，运行时间增长多快？大 O 记号用「只保留增长最快的一项、忽略常数系数」的方式给出这个增长速度的上界，使我们可以脱离具体机器与代码细节，比较算法本身的优劣。

算法原理

设算法的基本操作次数为 T(n)。若存在常数 c 与 n₀，使得对所有 n ≥ n₀ 都有 T(n) ≤ c·g(n)，则记 T(n) = O(g(n))。实践中只需把 T(n) 的表达式取最高阶项并去掉系数：

例：T(n) = 3n² + 7n + 12
    去掉低阶项 7n、12   →  3n²
    去掉常数系数 3      →  n²
故 T(n) = O(n²)

规则速记：
    O(c) = O(1)                常数不算复杂度
    O(c·n) = O(n)              系数忽略
    O(n² + n) = O(n²)          低阶忽略
    循环嵌套按「总执行次数」合并，不简单相乘

同一算法在不同数据上耗时不同，因此区分三种情形：最坏复杂度（所有规模 n 的输入中最慢的一个，保证「绝不超过」）、平均复杂度（等概率假设下的期望，如快排 O(n log n)）与最好复杂度（最有利的输入，如冒泡 O(n)）。竞赛与工程中通常按最坏情形评估，只有当平均/最好有独立价值（如快排、哈希）时才单列。

常见增长阶由慢到快（越好）排列为：

O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(2ⁿ) < O(n!)
为什么 O(2ⁿ) 与 O(n!) 几乎不可接受

指数级与阶乘级的增长速度完全不在人类直觉之内：n = 20 时 2ⁿ ≈ 1.05×10⁶ 尚可，n = 60 时 2⁶⁰ ≈ 1.15×10¹⁸ 已超过现代计算机 1 秒约 10⁸ 次运算的百年量级；n = 26 时 26! ≈ 4.03×10²⁶，按 10⁸ 次/秒要算约 1.28×10¹¹ 年——比宇宙年龄（约 1.38×10¹⁰ 年）还长。经验法则：一旦复杂度是 2ⁿ 或 n!，n 一般不能超过 20~24。

以 1 秒约 10⁸ 次基本运算估算可行规模：令 f(n) ≤ 10⁸ 反解 n——O(n) 可到 10⁸；O(n log n) 约 5×10⁶~10⁷；O(n²) 约 10⁴；O(n³) 约 460；O(2ⁿ) 约 26；O(n!) 约 12。

应用与局限

复杂度是上界估计而不是精确耗时：同为 O(n) 的算法常数可相差几十倍；访问模式影响缓存命中率（按行遍历二维数组远快于按列）；语言本身亦有数量级差异（C++ 对 Python 约 10~100 倍）。因此估算时通常把 10⁸ 视为 C++ 秒级时限下「基本操作」的标尺，Python 需再除以 10~100。竞赛中常见的做法是由数据范围反推可行复杂度：

数据范围 n ≤可接受复杂度（约）常见考点
