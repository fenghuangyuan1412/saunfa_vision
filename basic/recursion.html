递归 & 分治

递归（Recursion）是函数在其定义中直接或间接调用自身的写法：把问题化为「同形状的更小问题」，直到命中边界条件后逐层返回。分治（Divide and Conquer）是递归最重要的应用范式：分解 → 递归求解子问题 → 合并结果。本页以汉诺塔为例，同时观察递归调用栈的压入与弹出。

算法原理

递归三要素：

  • 边界条件（base case）：最小规模下可直接回答，不再递归。缺失边界会导致无限递归直至栈溢出。
  • 自相似：子问题与原问题结构相同，只是规模更小，因此可以复用同一段代码。
  • 规模缩小：每次递归调用都必须让问题严格变小（如 n 变为 n-1 或 n/2），保证有限步内到达边界。

调用栈：每次函数调用压入一帧，保存实参、局部变量与返回地址；函数返回时弹栈并回到调用点继续执行。递归深度就是栈的最大帧数，这也是递归的空间代价。

汉诺塔：三根柱子 A、B、C，A 上从底到顶叠着 n 个大小互异的盘。要求把所有盘移到 C，每次只能移动一个盘，且任何时刻大盘不能位于小盘之上。设 hanoi(k, from, to, aux) 表示「把 from 柱顶部最小的 k 个盘整体搬到 to」，则：

  1. 上面 k-1 个盘先借助 to 搬到 aux；
  2. 剩下的最大盘（盘 k）直接从 from 搬到 to；
  3. 再把 aux 上的 k-1 个盘借助 from 搬到 to。
function hanoi(k, from, to, aux):        // 把 from 顶部最小的 k 个盘搬到 to
    if k == 0: return                    // 边界：没有盘需要搬
    hanoi(k - 1, from, aux, to)          // 分治：上层 k-1 个盘暂存到 aux
    move(disk k, from, to)               // 合并：最大的盘单独搬到 to
    hanoi(k - 1, aux, to, from)          // 分治：暂存的 k-1 个盘归位到 to

记 T(k) 为搬 k 个盘所需的移动次数，则 T(k) = 2T(k-1) + 1，T(0) = 0，解得 T(k) = 2^k − 1。

分治的一般形式与主定理直觉：若把规模 n 的问题分成 a 个规模 n/b 的子问题，合并代价为 O(n^d)，则递归式 T(n) = a·T(n/b) + O(n^d)。比较「子问题个数带来的增长 log_b a」与「合并代价的增长 d」：谁的增长更快，谁就决定总复杂度；两者相当时（d = log_b a）多出一个对数因子。例如归并排序 a=2, b=2, d=1，log_2 2 = 1 = d，故 T(n) = O(n log n)。

注意：递归深度与爆栈

递归的深度受调用栈容量限制。对 n = 10^5 量级的线性递归（如求 n! 的朴素递归、链式 DFS），常见的默认栈大小（约 1 MB，容纳上万帧）会被耗尽，产生栈溢出（Stack Overflow）。工程与竞赛中的对策：① 改写为迭代 + 显式栈，把「帧」放进数组自行管理，栈空间搬到堆；② 加深栈限制（不总是可行）；③ 用记忆化或递推消除重复子问题，如把斐波那契递归改为 O(n) 递推。汉诺塔的递归深度只有 n，但移动次数是 2^n − 1：它「栈不深但指数慢」，正好说明深度与时间复杂度是两个独立维度。

应用与局限

分治的典型应用：归并排序 / 快速排序（拆分数组后递归再合并）、最大子数组和（答案要么在左半、要么在右半、要么跨越中点，取三者最大，可得 O(n log n) 解法，线性 DP 解法见 最大子段和）、最近点对（按 x 排序后二分，合并时只需检查带状区域内常数个点，O(n log n)）、快速幂与矩阵幂（把指数折半）、FFT 与大整数乘法。

局限：① 存在重叠子问题时朴素递归会指数爆炸（如斐波那契），需记忆化或改递推；② 深递归有爆栈风险，可用显式栈模拟把递归改写为迭代——本页右侧的调用栈正是这种显式管理的对象，把「压栈/弹栈」写进数组就能改造成非递归版本；③ 每层函数调用有常数开销，纯性能场景下手工迭代往往更快。
