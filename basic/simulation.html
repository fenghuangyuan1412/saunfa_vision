模拟

模拟法（Simulation）不追求巧妙的数学公式，而是忠实翻译题目规则：把系统的状态完整记录下来，按题意规定的事件顺序一步一步推进，直到得到答案。只要状态选取得当、顺序不出错，模拟几乎总能得到正确解，代价通常是较高的时间复杂度。

算法原理

写模拟题的关键有三点：① 状态选取——哪些量会随时间变化（位置、剩余集合、计数器、轮次），用变量或数组一一对应，不能漏；② 事件顺序——同一步内多个动作的先后（先报数还是先出圈、边界上从哪个方向推进）必须严格对照题意；③ 循环终止条件——什么时候停。以约瑟夫环为例：n 个人围成一圈编号 1~n，从某个人开始依次报数，报到 m 的人出圈，下一个人重新从 1 开始报，如此往复直到圈中只剩 1 人。用数组维护「仍在圈中」的标记，配一个当前指针向后移动即可。

procedure josephSim(n, m):
    alive[1..n] = true        // 是否仍在圈中
    cur = 0, outCount = 0     // cur：当前位置指针（0 表示从 1 号前开始）
    while 剩余人数 > 1:
        重复 m 次: cur 向后移动到下一个 alive 的人   // 报数 1..m
        alive[cur] = false    // 报到 m 的人出圈
        outCount += 1
        记录出圈顺序 outSeq[outCount] = cur
        // 下一轮从 cur 的下一个存活者继续报数
    幸存者 = 唯一的 alive 位置
提示：模拟 vs 公式解法

约瑟夫环存在 O(n) 递推 f(i) = (f(i−1) + m) mod i（f 为 i 人时幸存者 0 基编号），完全不需要维护圈。取舍原则：规则复杂、状态多（多变量联动、地图推进）时模拟直观可靠；规则单一、规模巨大（如 n = 10⁹）时必须找公式或周期性。模拟题最容易错在「顺序」与「边界」，写完务必用样例逐步打表核对前几步。

复杂度分析

指标量级说明
最优时间复杂度O(n·m)数组标记模拟：共出圈 n−1 人，每人报数 m 次，每次在圈中向后移动；输入不影响总步数
平均时间复杂度O(n·m)同上，报数总次数恰为 (n−1)·m（跳过已出圈者不增加报数次数）
最坏时间复杂度O(n·m)朴素「逐格检查是否存活」的实现会退化为 O(n²·m)；用环形链表可到 O(n·m)
空间复杂度O(n)alive 标记数组 + 出圈顺序表
公式解法O(n) 时间 / O(1) 空间递推 f(i)=(f(i−1)+m) mod i，f(n)+1 即幸存者编号

应用与局限

模拟是竞赛「入门档」题目的主流考法（如扑克发牌、棋盘机器人行走、排队报数、日期推进），也是检验题意理解是否准确的直接手段。局限在于：它只是把规则「重放」一遍，复杂度往往与事件发生次数成正比，当数据范围达到 10⁹ 次操作时不可接受，需要用周期发现、跳跃推进（倍增）、数学公式优化。约瑟夫环的递推 f(i) = (f(i−1) + m) mod i 就把 O(n·m) 的模拟降为 O(n)；m = 2 时更有闭合解（幸存者 = 2·(n − 2^⌊log₂n⌋) + 1）。按 10⁸ 次运算/秒估算，模拟 n = 10³、m = 10³（10⁶ 次）毫无压力，n = m = 10⁵ 就已经到极限。
