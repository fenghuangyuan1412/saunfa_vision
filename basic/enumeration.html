枚举

枚举（穷举，Exhaustive Search）是最基本、最普适的算法思想：把候选解的集合完整（或按规则部分）地罗列一遍，逐一检验是否满足条件。它保证正确性，代价是候选量可能指数级大——因此枚举的核心手艺是选对枚举对象、压小枚举范围、配合剪枝。

算法原理

设计枚举先回答三个问题：枚举什么（对象是排列、子集、区间还是三元组）；在多大范围内枚举（能否用对称性去重、用约束提前排除）；每个候选花多少代价检验（能否用前缀和之类的预处理把检验降为 O(1)）。总代价 = 候选个数 × 单点检验代价，任何一项的降低都直接加速整体。

// 子集枚举的位运算技巧：n ≤ 20 左右时可用
// 用整数 s 的二进制第 i 位表示「第 i 个元素是否入选」
procedure enumerateSubsets(A[0..n-1], S):
    for s = 0 to (1 << n) - 1:          // 共 2ⁿ 个掩码
        sum = 0
        for i = 0 to n - 1:
            if (s >> i) & 1 == 1:        // 第 i 位为 1
                sum = sum + A[i]
        if sum == S:
            output 方案 s                // 命中一个子集和为 S 的方案

// 常见变体：
//   子集和的增量枚举：lowbit 递推，单次 O(1)
//   枚举三元组 i < j < k：三重循环配合前缀信息降为 O(n²)
//   配合剪枝：sum 已超过 S 时 return，候选量远小于 2ⁿ
提示：缩小枚举量的三板斧

① 利用约束：枚举 a ≤ b ≤ c 而非全部排列，量降 6 倍；② 利用对称性：只枚举一半方案再镜像补全；③ 利用前缀信息：把「检验一个候选」从 O(n) 降为 O(1)（如前缀和判区间）。当 2ⁿ 仍太大时，改用折半搜索（meet in the middle）：把集合分成两半各枚举 2^(n/2)，排序后双指针合并。

复杂度分析

指标量级说明
最优时间复杂度O(2ⁿ·n)本演示枚举全部 2ⁿ 个掩码收集所有方案，不存在「提前停」；若只求一个解，最好情形 s=0 即停为 O(n)
平均时间复杂度O(2ⁿ·n)2ⁿ 个掩码 × 每个掩码 O(n) 求和；用 lowbit 递推可降到 O(2ⁿ)
最坏时间复杂度O(2ⁿ·n)必须检查完所有子集（如无解时）
空间复杂度O(n)原数组 + 当前子集；存储全部方案另算
方案总数2ⁿn = 5 时 32 个；n = 20 时约 1.0×10⁶ 个

应用与局限

位掩码枚举适用于子集和、划分方案、TSP 状压 DP 的基底等场景。局限非常明确：2ⁿ 增长太快，按 10⁸ 次运算/秒估算，n ≤ 20 时 2ⁿ·n ≈ 2×10⁷ 轻松；n = 24 时约 4×10⁸ 接近极限；n ≥ 30 就完全不可行。此时可：只枚举「一半」再合并（折半搜索，把 2ⁿ 降到 2^(n/2)·poly）；加剪枝减少实际访问的掩码；或改用 DP 换掉指数枚举。枚举也是验证暴力答案、对拍找规律的可靠工具。
